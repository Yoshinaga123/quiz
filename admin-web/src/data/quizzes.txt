## セクション2: ビルドツール & Asset 管理

### 問題4: Vite での Asset 読み込み方式の違い
以下のファイル配置について、```fetch("/data.json")``` でアクセス可能なのはどれですか？

A) src/data/data.json
B) public/data.json
C) dist/data.json（ビルド後）
D) A と C

正解: B
出典: Vite Official Documentation - Static Asset Handling

理由:
- src/ 配下のファイルは、ビルド時に JavaScript にバンドルされます
- そのため、HTTP リクエストで直接アクセスできません
- import で JavaScript 内に読み込む必要があります

```typescript
// src/data.json にアクセスする場合（import方式）
import data from "./data.json";
```

### 問題5: src/ 方式 vs public/ 方式 の使い分け
クイズアプリで、クイズの複数バージョンを サーバー側で動的に配信し、
その日のクイズをランダムに読み込みたい場合、最適な配置方式はどちらですか？

A) src/data/quizzes.json にすべてのバージョンを保存し、ビルド時にバンドルする
B) public/quizzes/ フォルダに複数ファイルを保存し、fetch() で動的に取得する
C) バックエンド API から動的に取得する
D) TypeScript の enum で定義する

正解: C
補足:
- public/ 方式は静的配信向き（毎日変わるデータには不向き）
- サーバー側で「本日のクイズ」を決定し、API で配信する設計が推奨

出典: Vite Documentation, React Best Practices

### 問題6: バンドルサイズの最適化
以下のうち、最終的なブラウザのダウンロードサイズが最も小さくなるのはどれですか？

A) assets.json を src/data/ にインポートして、すべてのクイズをバンドルする
B) index.html から <script src="./quizzes.js"></script> で別途読込み
C) public/ に置いて動的に fetch() し、必要な分だけ読込み
D) バックエンド API から遅延ロード（Lazy Load）で配信

正解: C または D（最適: D）
理由:
- src/ バンドル：すべてがメインバンドルに含まれ、最初のロードが重い
- 静的な別ファイル：キャッシュ効率が良いが、すべてダウンロードされる
- public + fetch：必要なファイルだけ取得でき、code splitting も可能
- API + Lazy Load：サーバー側で配信制御でき、最も柔軟で最適

出典: Web Performance Best Practices, Vite Code Splitting Guide

## セクション5: パフォーマンス・セキュリティ

### 問題9: localStorage を使った「訪問回数」カウントの注意点
以下のコードで、最も問題になる可能性があるのはどれですか？

```typescript
useEffect(() => {
  const stored = localStorage.getItem("visitCount");
  const count = stored ? parseInt(stored, 10) : 0;
  const newCount = count + 1;
  localStorage.setItem("visitCount", String(newCount));
  setVisitCount(newCount);
}, []);
```

A) localStorage はシークレットモードで動作しない可能性
B) ユーザーがブラウザの開発者ツールで値を改ざん可能
C) キーが重複すると値が上書きされる
D) parseInt の基数指定（第2引数の 10）がないと、'08' が8進数となるバグになる可能性

正解: B
補足: 
- 正解回数や スコアのような重要データは localStorage で管理すべきではない
- サーバーサイドで管理し、JWT など認証トークンで検証する必要がある
- localStorage は「ローカル設定」（テーマ、言語設定など）向き

出典: OWASP - Client-side Storage Security

### 問題10: クイズアプリの基本セキュリティ
管理画面でクイズを作成・更新するとき、最初に実装すべき認証・認可は？

A) メールアドレスのみで認証
B) JWT トークン + ロールベース認可（RBAC）
C) セッションクッキー + CSRF トークン
D) A と B

正解: B
理由:
- 複数アプリを運用する場合、JWT の scope/role で権限制御が容易
- API 呼び出しごとに検証可能（モバイル ↔ Web の共通認可ロジック）
- セッションクッキーはサーバーサイド状態を維持するため、スケーラビリティに課題
- CSRF 対策は必須ですが、JWT + SameSite クッキーで対応可能

実装順序:
1. JWT 発行・検証（バックエンド）
2. role/scope を含める（admin, user など）
3. 管理画面で Authorization ヘッダーに JWT を付与
4. バックエンド側で role を確認して、削除・編集を許可 / 拒否

出典: OWASP - Authentication Cheat Sheet, JWT Best Practices

### 問題12: Vite + React + TypeScript の推奨プラグイン
Vite で React + TypeScript を使用する場合、公式推奨のプラグインはどれですか？

A) babel-plugin-react-compiler
B) @vitejs/plugin-react
C) react-compiler
D) tsx-loader

正解: B
理由:
- Vite は ESM ベースで、Babel は不要

`vite.config.ts` での設定:
```typescript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
})
```

## セクション7: React Router の実装パターン

### 問題13: React Router のルート保護（Route Protection）
クイズアプリで、管理画面は認証済みユーザーのみがアクセス可能にする実装方法として、最も推奨されるのはどれですか？

A) ルートコンポーネント内で useEffect で認証確認し、未認証なら手動で redirect
B) ルートを定義する際、loader 関数で事前認証確認し、unauthorized なら throw redirect
C) ページ遷移時に useNavigate で手動チェック
D) クライアント側の状態だけで判定

正解: B
理由:
- loader 関数はルート遷移前に実行される
- 認証失敗の場合、コンポーネント描画の前に redirect 可能
- UX が良く、不正アクセス試行のログもとりやすい

実装パターン:
```typescript
export const adminRoute = {
  path: "admin",
  lazy: () => import("./admin"),
  loader: async ({ params }) => {
    const isAuthed = await checkAuth();
    if (!isAuthed) {
      throw redirect("/login");
    }
    return {};
  }
}
```

出典: React Router Documentation - Route Protection, Loader Pattern

### 問題14: Index ルート と Lazy Loading の組み合わせ
以下のルート定義で、`/admin` にアクセスした場合、どれが実行されますか？

```typescript
export default [
  {
    path: "admin",
    lazy: () => import("./admin/layout"),
    children: [
      { index: true, lazy: () => import("./admin/dashboard") }
    ]
  }
] satisfies RouteConfig;
```

A) admin/layout のみロード
B) admin/dashboard のみロード
C) admin/layout と admin/dashboard の両方ロード
D) ルート遷移時にロード、コンポーネント描画時には未ロード

正解: C
理由:
- `path: "admin"` → admin/layout をロード
- `index: true` → 追加パスなし ($PATH/admin) に対応
- lazy() により、両方がコード分割される

このパターンで、`/admin` アクセス時は:
1. admin/layout がロード → <Outlet /> で子を表示
2. admin/dashboard がロード → <Outlet /> に挿入

出典: React Router Documentation - Code Splitting with Lazy

## セクション8: キャッシング と データ再取得戦略

### 問題15: Request Deduplication（リクエスト重複排除）
同一の問題データを複数ページから fetch する場合、Request Deduplication を実装する利点は？

A) 同じ fetch() 呼び出しが並行実行される場合、1回のリクエストで統合し複数ページに配信する
B) キャッシュ層を追加して、ネットワークリクエストを削減する
C) バックエンド側で重複クエリをフィルタリング
D) A と B

正解: A
理由:
- 単一のネットワークリクエストで、複数のコンポーネント・ページから参照される
- 競合状態（race condition）を回避
- API 負荷を削減

実装パターン（キャッシュ + deduplication）:
```typescript
const cache = new Map();

async function fetchQuiz(quizId: string) {
  if (cache.has(quizId)) {
    return cache.get(quizId);
  }
  const promise = fetch(`/api/quiz/${quizId}`).then(r => r.json());
  cache.set(quizId, promise);
  return promise;
}
```

出典: TanStack Query Documentation - Request Deduplication

管理画面でクイズを編集後、ユーザー画面の「クイズ一覧」キャッシュを無効化する実装として、最も推奨されるのはどれですか？

B) setInterval で定期的に refetch

```typescript
const mutation = useMutation({

})
```

## セクション9: HTML メタデータとパフォーマンス

### 問題17: First Contentful Paint（FCP）と CSR/SSR の選択
「クイズ管理画面は SEO が不要で、初期描画速度を重視する必要がない」という要件での最適な実装はどれですか？

A) SSR（Server-Side Rendering）で最初のHTMLに全コンテンツを含める
B) CSR（Client-Side Rendering）- JavaScript 実行後にコンテンツを描画
C) SSG（Static Site Generation）で事前生成
D) ISR（Incremental Static Regeneration）

正解: B
理由:
- 管理者向けの内部ツールなので、SEO 不要
- **FCP 最適化の必要がない**（管理者は多少の遅延を許容）
- CSR はシンプルで保守性が高い

補足: ユーザー向けのクイズ本体は FCP が重要なため、SSR or Next.js サイドでもいい設計が必要です。

出典: Web Performance - First Contentful Paint, Routing Strategies

### 問題18: Response Shape Validation（レスポンス形状検証）
バックエンド API からのレスポンスが期待する形式かを確認する処理を「Response Shape Validation」といいます。最も安全な実装はどれですか？

A) typeof チェックと === での厳密等価比較
B) JSON.parse の try-catch のみ
C) zod や io-ts などスキーマバリデーションライブラリ
D) ユーザー入力のバリデーションと同じロジック

理由:

```typescript
const QuizResponseSchema = z.object({

  correctAnswer: z.number(),

const parsed = QuizResponseSchema.parse(apiResponse);
```

## セクション10: フォーム処理 と UX

### 問題19: React Hook Form での送信中ガード
クイズ編集フォームで、ユーザーが「保存」ボタンを連打するのを防止する実装方法として推奨されるのはどれですか？

A) onClick で submit 後、手動で `disabled = true` 設定
B) React Hook Form の `formState.isSubmitting` を使用
C) useState で送信フラグを管理
D) form の disabled 属性を合わせせて制御

正解: B
理由:
- React Hook Form の `isSubmitting` は送信中を自動追跡
- ボタン `disabled={isSubmitting}` だけで OK
- フォームの各フィールドも `disabled={isSubmitting}` 可能

実装例：
```typescript
const { handleSubmit, formState: { isSubmitting } } = useForm();

return (
  <form onSubmit={handleSubmit(onSubmit)}>
    <input {...register("title")} disabled={isSubmitting} />
    <button type="submit" disabled={isSubmitting}>
      {isSubmitting ? "保存中..." : "保存"}
    </button>
  </form>
);
```

出典: React Hook Form Documentation - formState.isSubmitting

### 問題20: npm のバージョン指定エラー ETARGET
npm install 実行時に「ETARGET: No matching version found」というエラーが出た場合、最初に確認すべきことはどれですか？

A) npm cache を削除して再実行
B) package.json の依存バージョン指定が正確か確認
C) npm/node のバージョン互換性確認
D) インターネット接続確認

正解: B
理由:
- **ETARGET = 指定したバージョンがレジストリに存在しない**
- `npm view パッケージ名` でレジストリに存在するバージョンを確認

例：
```bash
# エラー例
npm install react@99.0.0  # 存在しないバージョン

# 確認方法
npm view react versions  # 利用可能なバージョン一覧

# 修正方法
npm install react@latest  # または npm install react@18.2.0
```

補足:
- Vite で React Compiler を使う場合も、バージョン互換性を要確認
- alpha/beta バージョンの場合、`npm install パッケージ@next` なども有効

出典: npm Error Messages Documentation
