# Burp Suite — OWASP Top 10 対応・限界まとめ

## 総合評価

Burp Suite Professional は 3 ツール中最も高い検出精度を持つが、**有料ライセンスが必要な機能が多いこと・ビジネスロジックの自動評価は不可能なこと**が主な限界。Community 版は自動スキャンが使えないため手動テストが前提となる。

---

## A01: アクセス制御の不備 (Broken Access Control)

| 項目 | 内容 |
|------|------|
| **対応度** | ◎ 高い (拡張機能込み) |
| **できること** | **Autorize 拡張**を使うことで IDOR・水平権限昇格を半自動で検出 / 強制ブラウジングで未認可パスへのアクセスを確認 / Repeater で手動による権限テストが容易 |
| **できないこと** | Autorize なし (標準機能のみ) では IDOR の自動検出は不可 / ビジネスロジックに依存した垂直権限昇格の完全自動検出は不可 |
| **根本的な理由** | IDOR の検出は「このリソースが誰に属するか」という仕様の理解が必要。Autorize は 2 ユーザのレスポンスを比較することで半自動化しているが、最終的な判断は人間が行う必要がある |

> **Community 版**: Autorize は使用可能。ただし手動操作が必須

---

## A02: 暗号化の失敗 (Cryptographic Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ◎ 高い |
| **できること** | HTTP での機密情報送信の検出 / Cookie の `Secure` / `HttpOnly` / `SameSite` フラグ不備 / 弱い TLS バージョン・暗号スイートの検出 / レスポンス内のクレジットカード番号・秘密鍵の露出検出 |
| **できないこと** | サーバサイドの暗号実装 (乱数生成・鍵長・鍵管理) の評価 / 証明書の有効期限管理の評価 |
| **根本的な理由** | サーバ内部の暗号処理ロジックは HTTP 通信からは観測できない |

**補完手段**: testssl.sh (TLS 詳細分析) / SAST ツール (コード解析)

---

## A03: インジェクション (Injection)

| 項目 | 内容 |
|------|------|
| **対応度** | ◎ 非常に高い |
| **できること** | SQL インジェクション (エラーベース・ブラインド・時間ベース・**OOB**) / XSS (反射型・格納型・DOM ベース) / OS コマンドインジェクション (**Blind も Collaborator で検出**) / SSTI / LDAP / XPath / XXE (**Blind XXE も対応**) |
| **できないこと** | 完全に新規の未知のインジェクション手法への即時対応 / クライアントサイドのみで完結するインジェクション (オフライン処理など) |
| **根本的な理由** | Burp Collaborator による OOB 検出で Blind 系の多くはカバーできるが、アプリケーション固有のコードを読みにくく変換（難読化）・エンコードによってテストデータが無効化されるケースがある |

> **Community 版**: Active Scanner (自動スキャン) が使えないため Repeater / Intruder での手動確認が必要

---

## A04: 安全でない設計 (Insecure Design)

| 項目 | 内容 |
|------|------|
| **対応度** | △ 部分的 (手動テスト前提) |
| **できること** | Repeater・Intruder を使った**手動でのビジネスロジックテスト**が容易 (例: レート制限テスト、フロースキップの確認) |
| **できないこと** | ビジネスロジックの欠陥の**自動検出**は不可 / 設計レベルの問題 (例: 脅威モデルの欠如) の評価は不可 |
| **根本的な理由** | 「正しい設計」の基準はアプリケーションの仕様によって異なるため、どのツールも自動化できない領域 |

**補完手段**: 脅威モデリング (STRIDE など) / 手動テスト / コードレビュー

---

## A05: セキュリティの設定ミス (Security Misconfiguration)

| 項目 | 内容 |
|------|------|
| **対応度** | ◎ 高い |
| **できること** | セキュリティヘッダの網羅的チェック (`CSP`, `HSTS`, `X-Frame-Options`, `Permissions-Policy` など) / ディレクトリリスティング / エラーページによるサーバ情報漏洩 / 不要な HTTP メソッドの検出 / デフォルト認証情報のテスト |
| **できないこと** | クラウド・インフラ層の設定ミス (S3 バケット公開など) / ファイアウォール・ネットワーク設定の評価 |
| **根本的な理由** | Burp Suite は Web アプリケーション層に特化しており、インフラ・OS 層には届かない |

> **Community 版**: パッシブスキャンは動作するため、ヘッダ不備は自動検出される

---

## A06: 脆弱なコンポーネント (Vulnerable and Outdated Components)

| 項目 | 内容 |
|------|------|
| **対応度** | ○ 良好 (拡張機能込み) |
| **できること** | **Retire.js 拡張**で JavaScript ライブラリの脆弱なバージョンを検出 / サーバヘッダからフレームワーク・バージョン情報を取得 |
| **できないこと** | サーバサイドの依存関係の完全把握 / `package.json` / `pom.xml` などのマニフェストファイルの直接解析 |
| **根本的な理由** | Burp Suite は通信上のデータのみを解析するため、バンドル・コードを読みにくく変換（難読化）された依存関係の特定が困難な場合がある |

**補完手段**: OWASP Dependency-Check, Snyk, npm audit などの SCA ツール

---

## A07: 認証・セッション管理の失敗 (Identification and Authentication Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ◎ 非常に高い |
| **できること** | **Sequencer** によるセッショントークンのエントロピー統計分析 / セッション固定化の検出 / Cookie 属性の不備検出 / Intruder による認証ブルートフォース / **JWT Editor** 拡張による JWT 脆弱性検出 (`alg: none` / 弱い秘密鍵 / アルゴリズム混乱攻撃) |
| **できないこと** | MFA (多要素認証) の実装品質の自動評価 / パスワードリセットフローの完全自動テスト |
| **根本的な理由** | MFA やパスワードリセットは複数ステップ・複数チャネル (メール・SMS など) をまたぐため完全自動化が困難 |

> **Community 版**: Sequencer・JWT Editor は使用可能。Intruder は速度制限あり

---

## A08: ソフトウェアとデータの整合性の失敗 (Software and Data Integrity Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ○ 良好 (部分的) |
| **できること** | SRI (`integrity` 属性) 未設定の外部スクリプト読み込みを検出 / 安全でないデシリアライゼーションの検出 (Scanner) |
| **できないこと** | CI/CD パイプラインの安全性評価 / ビルド成果物の署名検証 / サプライチェーン攻撃の検出 |
| **根本的な理由** | CI/CD・サプライチェーンは Web アプリの HTTP 通信から観測できないビルド・デプロイプロセスの問題 |

**補完手段**: Sigstore, SLSA フレームワーク, GitHub Actions セキュリティスキャン

---

## A09: セキュリティログ・監視の失敗 (Security Logging and Monitoring Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ✕ 対応不可 |
| **できること** | なし |
| **できないこと** | サーバ上でログが適切に記録されているかの確認 / アラート機能の有無・設定の評価 / インシデント検知体制の評価 |
| **根本的な理由** | これはサーバ内部・運用プロセスの問題であり、HTTP 通信を観測する Burp Suite では評価できない |

**補完手段**: ログ監査・SIEM 設定のレビュー / インフラチームとの連携

---

## A10: サーバサイドリクエストフォージェリ (SSRF)

| 項目 | 内容 |
|------|------|
| **対応度** | ◎ 非常に高い |
| **できること** | エラーベース SSRF の検出 / **Burp Collaborator を使った Blind SSRF の確実な検出** (DNS / HTTP コールバック) |
| **できないこと** | 内部ネットワーク構成を知らなければ、SSRF で到達できるリソースの範囲を自動で特定することは難しい |
| **根本的な理由** | Blind SSRF の検出自体は Collaborator で可能だが、その後の「どこまで内部にアクセスできるか」の調査は手動テストが必要 |

> **Community 版**: Active Scanner がないため、Repeater を使った手動での SSRF テストが必要

---

## まとめ: Burp Suite が苦手な Top 10 カテゴリ

| カテゴリ | 理由 |
|---------|------|
| **A04 安全でない設計** | ビジネスロジックの自動評価は不可 (手動テストで補完) |
| **A06 脆弱なコンポーネント** | サーバサイドの依存関係の完全把握は困難 |
| **A08 整合性の失敗** | CI/CD・サプライチェーンは検査範囲外 |
| **A09 ログ・監視の失敗** | サーバ内部の設定は観測不可 |

## Community 版の制限まとめ

| 機能 | Community | Professional |
|------|-----------|--------------|
| 自動スキャン (Scanner) | ✕ | ◎ |
| Intruder 速度 | △ 制限あり | ◎ 無制限 |
| Collaborator | ✕ | ◎ |
| Sequencer | ◎ | ◎ |
| JWT Editor (拡張) | ◎ | ◎ |
| Autorize (拡張) | ◎ | ◎ |
| Repeater | ◎ | ◎ |
| パッシブスキャン | ◎ | ◎ |

> Community 版では A03 (Blind 系) と A10 (Blind SSRF) の自動検出が事実上不可能。Pro 版では Collaborator によりこれらを大幅に補完できる。
