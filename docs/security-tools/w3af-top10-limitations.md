# w3af — OWASP Top 10 対応・限界まとめ

## 総合評価

w3af はプラグインベースで幅広い脆弱性を検出できるが、**メンテナンスが低調であること・JavaScript の動的解析が弱いこと・OOB 検出機能がないこと**が主な限界。

---

## A01: アクセス制御の不備 (Broken Access Control)

| 項目 | 内容 |
|------|------|
| **対応度** | △ 部分的 |
| **できること** | 強制ブラウジング (`forced_browsing` プラグイン) で未認可パスへのアクセスを検出 / HTTP メソッドのテスト |
| **できないこと** | IDOR の検出。ユーザ間の権限比較が必要な認可テストは自動化不可 / 水平・垂直権限昇格の網羅的なテスト |
| **根本的な理由** | w3af は単一ユーザのセッションで動作するため、「別ユーザのリソースにアクセスできるか」という比較テストを行う仕組みがない |

**補完手段**: 手動テスト・Burp Suite + Autorize 拡張

---

## A02: 暗号化の失敗 (Cryptographic Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ○ 良好 |
| **できること** | HTTP での機密情報送信の検出 (`grep/credit_cards`, `grep/passwords_profiler`) / Cookie の `Secure` フラグ未設定の検出 / HTTP から HTTPS へのリダイレクト未設定の検出 |
| **できないこと** | TLS バージョン・暗号スイートの詳細な分析 / サーバサイドの暗号実装 (鍵管理・乱数生成) の評価 |
| **根本的な理由** | w3af は TLS ハンドシェイクの詳細解析機能が弱く、暗号スイートの網羅的なテストには専用ツールが必要 |

**補完手段**: testssl.sh, sslscan

---

## A03: インジェクション (Injection)

| 項目 | 内容 |
|------|------|
| **対応度** | ◎ 高い |
| **できること** | SQL インジェクション (エラーベース・ブラインド) / XSS (反射型・格納型) / OS コマンドインジェクション / LDAP インジェクション / XPath インジェクション / SSTI / HTTP ヘッダインジェクション |
| **できないこと** | **帯域外 (OOB) インジェクション**の検出。DNS コールバックを使う Blind 系攻撃の確認が不可 / **最新の CVE に基づく新しいインジェクション手法**への対応 (メンテナンス低調のため) |
| **根本的な理由** | w3af に外部コールバックサーバ機能がなく、OOB での脆弱性確認ができない。また更新頻度の低さからペイロードが陳腐化している恐れがある |

**補完手段**: Burp Suite Professional + Collaborator / sqlmap (SQL インジェクションに特化)

---

## A04: 安全でない設計 (Insecure Design)

| 項目 | 内容 |
|------|------|
| **対応度** | ✕ 対応不可 |
| **できること** | なし |
| **できないこと** | ビジネスロジックの欠陥 / レート制限の欠如 / フローのスキップ / 設計上の認可不備 |
| **根本的な理由** | w3af はリクエスト・レスポンスのパターンで脆弱性を判断するため、アプリケーションの設計意図を評価できない |

**補完手段**: 脅威モデリング・手動テスト・コードレビュー

---

## A05: セキュリティの設定ミス (Security Misconfiguration)

| 項目 | 内容 |
|------|------|
| **対応度** | ○ 良好 |
| **できること** | ディレクトリリスティング / バックアップ・一時ファイルの露出 / エラーページによるサーバ情報漏洩 / デフォルト認証情報のテスト / 不要な HTTP メソッドの検出 |
| **できないこと** | セキュリティヘッダの網羅的チェックは ZAP・Burp と比べて精度が低い / クラウド・インフラ層の設定ミス |
| **根本的な理由** | w3af のセキュリティヘッダ関連プラグインは更新が少なく、最新のヘッダ (例: `Permissions-Policy`) に対応していない可能性がある |

---

## A06: 脆弱なコンポーネント (Vulnerable and Outdated Components)

| 項目 | 内容 |
|------|------|
| **対応度** | △ 部分的 |
| **できること** | サーバヘッダからフレームワーク・Web サーバのバージョン情報を取得 (`infrastructure/finger_apache`, `finger_iis` など) |
| **できないこと** | フロントエンドの JavaScript ライブラリのバージョン特定 / 依存関係マニフェストの解析 / **CVE データベースが古い可能性**があり最新の脆弱性を見逃す |
| **根本的な理由** | w3af のメンテナンスが低調なため、CVE データベースの更新が滞っている |

**補完手段**: OWASP Dependency-Check, Snyk, Retire.js

---

## A07: 認証・セッション管理の失敗 (Identification and Authentication Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ○ 良好 |
| **できること** | HTTP 基本認証・フォーム認証のブルートフォース / セッション固定化の検出 (`grep/session_fixation`) / Cookie の属性不備の検出 |
| **できないこと** | セッショントークンの統計的なランダム性分析 / MFA の評価 / OAuth / OIDC の実装検証 |
| **根本的な理由** | w3af にはトークンのエントロピー分析機能がない。また近年普及した OAuth 2.0 / OIDC フローへの対応が不十分 |

**補完手段**: Burp Suite Sequencer (エントロピー分析)

---

## A08: ソフトウェアとデータの整合性の失敗 (Software and Data Integrity Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ✕ 対応不可 |
| **できること** | なし |
| **できないこと** | SRI (Subresource Integrity) 未設定の検出 / CI/CD パイプラインの安全性評価 / サプライチェーン攻撃の検出 |
| **根本的な理由** | w3af にはセキュリティヘッダや SRI 属性を検査するプラグインが標準では含まれておらず、この領域は完全に対応外 |

**補完手段**: ZAP / Burp Suite のパッシブスキャン (SRI 未設定検出)

---

## A09: セキュリティログ・監視の失敗 (Security Logging and Monitoring Failures)

| 項目 | 内容 |
|------|------|
| **対応度** | ✕ 対応不可 |
| **できること** | なし |
| **できないこと** | サーバのログ設定・アラート機能・監視体制の評価はすべて対応外 |
| **根本的な理由** | HTTP 通信の外側にあるサーバ内部の設定を w3af が知る手段がない |

**補完手段**: ログ監査・SIEM 設定の手動レビュー

---

## A10: サーバサイドリクエストフォージェリ (SSRF)

| 項目 | 内容 |
|------|------|
| **対応度** | ○ 良好 (ただし制限あり) |
| **できること** | エラーメッセージやレスポンス差異を使った SSRF の検出 (`audit/ssrf` プラグイン) |
| **できないこと** | **Blind SSRF** の確実な検出。OOB コールバック機能がないため、サーバが応答を返さない SSRF は検出不可 |
| **根本的な理由** | DNS コールバックを受け取る外部サーバ機能がなく、Blind SSRF の証明ができない |

**補完手段**: Burp Suite Professional + Burp Collaborator

---

## まとめ: w3af が苦手な Top 10 カテゴリ

| カテゴリ | 理由 |
|---------|------|
| **A01 アクセス制御の不備** | IDOR など仕様依存の認可テストが自動化不可 |
| **A04 安全でない設計** | ビジネスロジックの評価は自動化不可 |
| **A06 脆弱なコンポーネント** | CVE データが陳腐化している可能性がある |
| **A08 整合性の失敗** | SRI・CI/CD は検査範囲外 |
| **A09 ログ・監視の失敗** | サーバ内部の設定は観測不可 |
| **A03・A10 (OOB・Blind 系)** | 外部コールバック機能がなく Blind 系脆弱性の検出が困難 |

> **特記事項**: w3af はメンテナンスが低調 (最終更新が古い) なため、上記の「できること」に分類した項目でも、最新の攻撃手法やフレームワークには対応していない可能性がある。本番環境のペネトレーションテストでは OWASP ZAP または Burp Suite との併用を強く推奨する。
