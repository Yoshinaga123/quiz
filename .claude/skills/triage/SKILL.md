# Investigating issues and PRs

Read [`AGENTS.md`](../../../AGENTS.md) first. That file is the operating manual. This skill only adds investigation procedure and the `.triage/` layout.

Produce a write-up the owner can act on without re-reading the thread. The deliverable is a file on disk, not only a chat message.

This skill is **read-only on GitHub**. Do not comment, label, assign, close, review, approve, or merge unless the user explicitly asks in this session. Posting, worktrees, and new-branch pushes follow `AGENTS.md` (`## Commenting on issues and PRs`, `## Iterating on a PR in a worktree`, `## Pushing a new branch`).

**Codex Cloud PR review is a different job.** When that is the task, follow `AGENTS.md` → `## Code Review Rules`. A `.triage/` write-up is optional then, not the published artifact.

If this skill and `AGENTS.md` disagree, `AGENTS.md` wins — especially the public-contract list, `## Rules`, `## Do not`, and `## Code Review Rules`.

## Where things live

`.triage/` is gitignored. Write freely.

```
.triage/
  issues/<N>/results.md
  prs/<N>/results.md
  issues/index.md          # generated by reindex.mjs
  prs/index.md             # generated
```

One directory per ticket, named by the bare GitHub number. Scratch files (`repro.ts`, `diff.patch`, `contract-notes.md`) sit beside `results.md`.

A TypeScript repro can use the root pad: copy the interesting lines into `play.ts` or a file under the ticket directory and run `npm run play` only when the pad itself is the experiment. Do not leave ticket repros in `packages/*/src/`.

### Writing from a PR worktree

A worktree has its own gitignored `.triage/`. Resolve the primary checkout and write there:

```bash
QUIZ_ROOT=$(git worktree list | head -1 | awk '{print $1}')
mkdir -p "$QUIZ_ROOT/.triage/prs/<N>"
```

Every write path starts with `$QUIZ_ROOT`. Investigate in the worktree, record in the root.

## results.md format

```yaml
---
number: 12
type: pr                    # pr | issue
status: done                # in-progress | done
verdict: merge-with-changes
title: "fix: keep public quiz list stable"
author: Yoshinaga123
url: https://github.com/Yoshinaga123/quiz/pull/12
investigated: 2026-08-18
---
```

Set `status: in-progress` as soon as you start. Flip to `done` only when the write-up stands alone.

`verdict` for **PRs**:

- `merge-as-is` — correct, tested, in scope.
- `merge-with-changes` — right idea; list the concrete edits.
- `needs-author-changes` — blocked on the author (repro, rebase, scope).
- `contract-incomplete` — public JSON shape changed without OpenAPI + fixtures + handwritten Zod + Go `publicQuiz` in the same PR. That is a defect.
- `decline` — out of scope or wrong approach. Give the one or two strongest reasons.
- `superseded` — already on `develop` / `main`. Name the commit or PR.
- `needs-owner-decision` — product call (for example ADR 0008 attempts API). State the tradeoff and a recommendation.

`verdict` for **issues**: `good-idea`, `already-fixed`, `needs-owner-input`, `not-recommended`, `needs-more-reproduction`, `duplicate` (add `duplicate_of: NNNN`).

After the frontmatter:

- `## Request` / `## Change` — what is asked or changed, in your own words.
- `## Current state` — what `develop` does today, with `file:line` references.
- `## Analysis` — correctness, public-contract completeness, tests, and the items in Cheap pass.
- `## Recommendation` — the action. Do not draft a maintainer-voice GitHub comment unless asked.

## Cheap pass (do this before a worktree)

Most defects here show up in the diff metadata. Disqualify and write the write-up from `gh` + the diff when any of these are true. The checklists live in `AGENTS.md`; do not invent a shorter list.

1. **Public contract** — JSON shape changed without the same-PR list in `AGENTS.md` → "Non-negotiable: public JSON contract". Verdict: `contract-incomplete`.
2. **Admin leak** — `status`, `pushEnabled`, `createdAt`, `updatedAt`, or seed-only `published` on `publicQuiz` (`AGENTS.md`).
3. **Secrets / product boundary** — `AGENTS.md` → `## Do not` and Code Review → Secrets.
4. **Tooling this repo does not want** — `AGENTS.md` → Code Review → Tooling (pnpm, nested lockfiles, emptied `.devcontainer`, `import * as z from "zod"`, OpenAPI-generated Zod, Biome unless TASK-005).

Default branch is `develop`.

```bash
gh issue view <N> -R Yoshinaga123/quiz --comments
gh pr view <N> -R Yoshinaga123/quiz --json number,title,author,state,isDraft,mergeable,baseRefName,additions,deletions,changedFiles,files
gh pr diff <N> -R Yoshinaga123/quiz
```

## Investigating an issue

No worktree. Read `develop`.

1. Read the whole thread with `gh`.
2. Search duplicates: `gh search issues --repo Yoshinaga123/quiz '…'` and grep `.triage/issues/*/results.md`.
3. Check `docs/backlog.md` and `docs/quiz-app-wbs.md` — the request may already be a named task or an explicit reject.
4. Reproduce against current source when the claim is behavioral. Do not invent a public field to "fix" a report.
5. Write `results.md`.

## Investigating a PR

If the cheap pass settles it, skip the worktree.

Otherwise:

```bash
git fetch origin pull/<N>/head:pr-<N>
git worktree add ~/.cursor/worktrees/quiz/pr-<N> pr-<N>
cd ~/.cursor/worktrees/quiz/pr-<N>
npm i
```

Do not use `gh pr checkout --detach`.

Then:

1. Read the diff in context. What did it touch that the author did not mention?
2. `git log --oneline origin/develop..HEAD` (or `main` if that is the base).
3. Run the tests the change implicates:
   - public contract: `npm run test:contract`
   - web / admin-web / Go together: `npm test`
   - Go only: `cd packages/backend && go test`
   - mobile DTO or Flutter UI: `cd packages/mobile && flutter test` (skip with a note if Flutter is not installed)
4. A schema or contract change without a success **and** failure test is unfinished.
5. Write `$QUIZ_ROOT/.triage/prs/<N>/results.md`.

Clean up when done:

```bash
cd "$QUIZ_ROOT"
git worktree remove ~/.cursor/worktrees/quiz/pr-<N> && git branch -D pr-<N>
```

Keep the worktree only when the verdict is `merge-with-changes` and you were asked to push.
